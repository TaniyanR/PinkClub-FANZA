# SEO・ランキング・IndexNow修正（2026-09-22）

対象: TaniyanR/PinkClub-FANZA。前回と同じ作業ブランチ `fix/restore-fanza-pages-db-setup-20260921` を使用。

## マージ後の操作

1. テストサイトへ反映し、管理画面の「SEO・IndexNow」を開きます。初回は「DBを更新する」を押してください。既存のインストーラーで未適用migrationを適用し、商品・管理者・設定を保持します。migration 023は3テーブルと集計用2インデックスを追加します。イベント件数が多い場合はインデックス作成に時間がかかるため、DBバックアップ後、アクセスの少ない時間帯で実行してください。
2. 商品・分類ページ、ランキング、サイトマップを確認してから本番へ反映します。本番側でも同じDB更新を行います。
3. 本番の「SEO・IndexNow」で表示された送信対象ドメインを確認して有効にします。キーは自動生成されます。「所有権確認ファイルを開く」で文字列だけが表示されることを確認してください。
4. 既存の `scripts/auto_import.php` のcronに送信処理を組み込んでいます。cronが未設定の場合は従来の「cron設定」を参照してください。独立した `php scripts/indexnow.php` でも処理できます。管理画面から手動送信も可能です。公開ページの表示中は送信しません。
5. 導入前の既存作品も通知したい場合は「既存作品の次の1,000件を送信待ちに追加」を使用します。繰り返すと続きから登録し、0件になれば完了です。通常の新規登録・更新では自動で送信待ちへ追加します。
6. 恒久的な配信終了・掲載終了が確認できた商品だけ、IDと確認理由を登録します。元のデータを残して410にし、「掲載終了を解除」で戻せます。従来の商品削除ボタンでも削除履歴を保存します。ただし、そのボタンで削除した実データは新機能の解除だけでは復元できません。

テストサイトではIndexNowを原則停止したまま確認してください。各環境のBASE_URLとDBを正しく設定します。設定済みの送信元と異なるドメインでは自動送信しません。DBをコピーした場合も、コピー先で明示的に有効化するまでは送信しません。

## 修正内容・影響範囲

- **HTTP応答:** 確認済み掲載終了のみ410/noindex。未知のURLは404。作品検索のDBエラーを404へ変換せず503/Retry-Afterにします。APIの未取得・障害・発売前という理由で一律410にはしません。
- **一覧・Sitemap・RSS:** 共通の公開商品条件から掲載終了商品を除外します。掲載終了登録・解除と固定ページ更新時にHTML/XMLキャッシュの世代を更新します。サイトマップはContent-Typeを保持して600秒キャッシュし、DB接続障害時は503にします。
- **ランキング:** PV + OUT×3の意味、既存の本日・週間・月間・年間を維持。NOW()で書かれる記録と同じDB時計で集計境界を計算します。200件分を保存して要求件数に切り出し、短い表示のキャッシュが一覧を欠落させる問題を修正。集計失敗時は直前の正常キャッシュを保持します。公開リクエストでは未生成でも集計せず、既存の背景更新・cronで更新します。初回未生成のランキングは更新完了まで空の場合があります。cronは最大2組ずつ巡回して負荷と偏りを抑えます。
- **IndexNow:** 公開正規URLの追加・更新・削除をDBキューへ保存。同一商品の内容が変わらない再取得は抑制。固定ページ作成・編集も通知。新規・更新は既存の2つの商品保存経路に接続しています。1回最大1,000件、公式API上限10,000件以内、TLS検証、固定送信先、リダイレクト追従なし、接続3秒/全体10秒制限。DBロックとrevision照合で並行更新を保護。200/202を受理として処理し、429・通信障害・サーバーエラーには間隔を空けて再送します。400/403/422は1日待機し、管理画面のHTTP結果から設定を確認できます。
- **metadata:** 日本語をバイト相当の幅で切りすぎないdescriptionへ変更。実データの作品名・出演者・メーカー・ジャンルを利用し、短い説明を補います。長さだけを満たす架空の女優名・メーカー名は入れません。`rating=adult`を1つ追加します。SafeSearch分類の申告であり、検索順位やスパム判定回避の保証ではありません。
- **VideoObject:** 正しいサンプル動画のuploadDate・画像・埋め込みURLが揃う場合だけProductのsubjectOfとして出力。元APIデータの `sampleMovieURL.uploadDate` が不明な場合は出力しません。商品発売日や今日をサンプル動画の投稿日として捏造しません。プレイヤーはembedUrlとし、商品ページを動画ファイルcontentUrlにしません。
- **OGP/SNS:** 既存のProduct・canonical・OGPの出力経路と画像を保持。成人向けタグ・descriptionの重複を追加しません。SNS crawler専用のHTMLキャッシュ迂回を除去し、一般閲覧と同じキャッシュを利用します。
- **速度:** ランキングの同期集計を除去、集計用索引、XMLキャッシュ、既存画像枠の寸法維持と非同期デコード。CSS/JSは更新版URLで長期キャッシュ。差し替えられる画像は1日とし、1年間古い画像が残るのを防ぎます。公開ページの外部API通信を追加しません。
- **セキュリティ:** 新管理画面は管理者認証と既存CSRF保護を使用。IndexNowは正規の公開ルートのみを許可し、任意URLや認証情報を送信しません。`.git`・`.env`・テスト/スクリプトディレクトリの公開アクセスとディレクトリ一覧を拒否。Referrer-Policyを今回指定のstrict-origin-when-cross-originへ統一します。HSTSは既存のHTTPS限定・当該ホスト限定を維持し、他のサブドメインへ一括適用しません。非推奨のX-XSS-Protectionは追加していません。

URL形式・FANZA APIパラメータ・アフィリエイトID/URL・リンクrel属性は変更していません。削除ファイルはありません。追加テーブルは `item_tombstones`、`indexnow_queue`、`indexnow_item_state` です。既存イベントの削除・再計算や過去日時の書き換えは行いません。

## 検証結果

### 実際に検証済み

PHP 8.3 / MariaDB 10.11の独立したテストDBで、インストール・migration再実行時のデータ保持、公開15ページ・管理3ページと新管理画面、商品/分類一覧、canonical/OGP、RSS/XML/robots、404/301、ログイン・CSRFを確認。

追加テストで、PV/OUTの得点、要求件数による欠落防止、未生成時の背景更新予約、SQL障害時の正常キャッシュ保持、410登録・解除・Sitemap除外、キャッシュ済み200→410→200、DB障害時503、配列入力拒否、IndexNowキー公開、URL範囲・重複・429再送待機・並行更新保持・202処理・別環境の送信抑止を確認しました。IndexNowへの送信結果は模擬応答で検証しており、実検索エンジンにはテストURLを送っていません。

PHP構文、JavaScript履歴テスト、差分チェックを実施。

### コード上確認済み

Apacheのrewrite/キャッシュ/セキュリティ設定、画像枠の既存CSS、cron・管理タイマー・2つの商品保存経路との接続、固定送信先/TLS/タイムアウト、サンプル動画の条件付き構造化データ。

### 実環境で確認が必要

- ApacheのAllowOverrideと必要モジュール、実デプロイ後のレスポンスヘッダー。
- Bingによるキー検証と実通知の200/202、cron実行ログ・再送結果。
- ブラウザのPC/スマートフォン表示、外部SNS crawler、PSI/Lighthouse/CWV実測。PSI 90点以上は未達成確認であり保証しません。
- Search Console/Bingのインデックス状況と検索流入の回復。

この実行環境からテスト・本番サイトへのHTTP確認はタイムアウト等で安定せず、公開後の動作を検証済みとはしていません。

404が40,545件、リダイレクトが31,410件という集計だけでは、各URLの正しい行き先や流入急落原因は特定できません。Search Consoleの対象URL一覧・リダイレクト元/先・発生日のエクスポートを使い、既存ページのURL変更なのか、未知のURLなのか、配信終了なのかを個別に判断する必要があります。既知の同一作品の別名URLから正規URLへの301は保持しています。無関係なトップページへの一括転送は行いません。
